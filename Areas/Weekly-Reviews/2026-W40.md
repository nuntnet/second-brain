## 🧠 สิ่งที่เรียนรู้สัปดาห์นี้

### MCP / OAuth

- **Headless eval กับดัก:** อย่า rename server config ขณะ eval รัน — credential หาย, session ถัดไป `needs-auth` ทั้งหมด
- **Claude Code OAuth:** ส่ง `http://localhost:<port>/callback` เสมอ (ไม่ใช่ 127.0.0.1) → Hydra client ต้อง register `localhost:3119`
- **Multi-company user + MCP metric:** user หลายบริษัทเรียก `whoami` ก่อน = ถูกต้อง → metric "first tool" ใช้ไม่ได้; วัด "first tool หลัง whoami" แทน

### Kubernetes / Oathkeeper

- **Oathkeeper dev = staging:** ทั้ง dev และ staging enforce `user.read offline` exact strategy เหมือนกัน — debug ด้วย `kubectl logs -n share deploy/oathkeeper`
- **BOLA Rule ไม่ระบุ config = Kratos staging:** Oathkeeper ตัวเดียวใช้ค่ากลาง → rule dev ปฏิเสธทุก dev session ถ้าไม่ระบุ config

### Architecture / Code Discovery

- **LINE OA channel_id = globally unique** ข้ามทุก workspace ทั้งระบบ — ย้าย OA ต้อง delete ที่ workspace เก่าก่อนเท่านั้น
- **`BindExistingBolaWorkspace`** เขียน `company_id` ให้เองในคำสั่งเดียว (CCS bind + BOLA write ไม่ต้องแยก)
- **บริษัทใหม่ 503 ≠ flag ปิด:** แปลว่าไม่มีแผน `bola_beta_free` — ไม่ถูก assign อัตโนมัติ
- **Company name rules ต่างกัน:** CCS = 2–128 char; OC2Plus = 5–50, Thai/Latin/digit/.-_+ เท่านั้น (เข้มกว่า)

### Security

- **Review-bot จับ SQL injection ที่คนมองข้าม (OC-4629 !666):** full-diff review คุ้มเสมอ — bot เห็นสิ่งที่ผ่านตามนุษย์ไป

### Broken Tools Found

- **`backfill_kratos_ids`:** binary ไม่ build เข้า Docker image + env var ผิดชื่อ — runbook พัง 2 ชั้น
- **`backfill_bola_registry`:** พัง 3 ชั้น — binary + dry-run ไม่อ่านจริง + ไม่ส่ง X-User-Id
- **Codex บน dev:** kratos-ui-go dev ไม่มี RFC 9207 → Codex login ไม่ได้ (แก้แล้วด้วย !195 บน share-dev)
