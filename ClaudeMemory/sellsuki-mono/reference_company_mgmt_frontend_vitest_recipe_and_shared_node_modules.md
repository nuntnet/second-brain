For `frontend/sellsuki-company-management-frontend` (vitest 1.6.1, Svelte 4):

- `npx vitest run --maxWorkers=4` fails with "options.minThreads and options.maxThreads must not conflict" and reports "no tests" — that is a collection error, not a green run. Use `--poolOptions.threads.minThreads=1 --poolOptions.threads.maxThreads=4`.
- The `rtk` hook mangles `npx vitest` output ("read: -3: invalid option"). Call `rtk proxy ./node_modules/.bin/vitest run ...` instead.
- A worktree has no `node_modules`; `ln -s <main checkout>/node_modules <worktree>/node_modules` works when `package-lock.json` is identical to the branch base (check `git diff origin/main -- package-lock.json` in the main checkout first). Remove the symlink before `git worktree remove`.
- Gates: `npx --no-install svelte-check --tsconfig ./tsconfig.json` (0 errors, ~800 pre-existing a11y warnings), `vite build --mode development`. There is no lint script. Whole suite on 2026-10-30: 221 files / 3871 tests in ~75 s.
- The pre-push secret guard (`gstack-redact-prepush`) false-positives on fake `-----BEGIN PRIVATE KEY-----SECRET` literals in KC test fixtures that are already on `origin/main`; it only trips when the pushed range contains those commits (e.g. the codex backup branch), not on a clean main-cut feature branch.

**Why:** each of these cost a failed run; a "no tests" result is easy to read as a pass.
**How to apply:** use this before running FE checks from a worktree. See [[reference_admin_fe_worktree_borrowed_node_modules_test_main_core]] for the sibling skew trap in the admin console repo.
